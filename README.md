# Restaurant Management System

Backend-приложение для управления рестораном, меню и заказами. Проект разработан на Java с использованием Spring Boot и PostgreSQL.

## Возможности

- Управление пользователями и их ролями.
- Управление категориями меню.
- Управление блюдами и напитками.
- Создание и управление заказами.
- Добавление нескольких позиций в один заказ.
- Отслеживание статуса заказа.
- REST API для взаимодействия с приложением.

## Технологии

- **Java 23**
- **Spring Boot 4**
- **Spring Data JPA**
- **Hibernate**
- **PostgreSQL 17**
- **Docker & Docker Compose**
- **Maven**
- **Lombok**
- **Jakarta Validation**

## Архитектура проекта

Проект организован по слоям:

- `models` — сущности базы данных.
- `repositories` — взаимодействие с базой данных через Spring Data JPA.
- `services` — бизнес-логика приложения.
- `controllers` — REST API и обработка HTTP-запросов.
- `enums` — перечисления ролей пользователей и статусов заказов.

## Основные сущности

### User

Пользователь системы.

Основные поля:
- `id`
- `username`
- `email`
- `password`
- `role`
- `createdAt`

Роли:
- `ADMIN`
- `COOK`
- `WAITER`

### Category

Категория меню, например кофе, десерты или основные блюда.

Основные поля:
- `id`
- `name`

### MenuItem

Блюдо или напиток в меню.

Основные поля:
- `id`
- `name`
- `description`
- `price`
- `category`

### Order

Заказ, содержащий общую информацию о заказе.

Основные поля:
- `id`
- `status`
- `createdAt`
- `user`

Статусы заказа:
- `NEW`
- `IN_PROGRESS`
- `READY`
- `COMPLETED`
- `CANCELLED`

### OrderItem

Отдельная позиция заказа.

Основные поля:
- `id`
- `quantity`
- `price`
- `order`
- `menuItem`

Один заказ может содержать несколько позиций, в том числе несколько разных блюд. Например, заказ может включать два капучино и одну порцию сырников.

## Запуск проекта

### Требования

Перед запуском убедитесь, что установлены:

- Java 23
- Docker
- Docker Compose
- Git

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd RestaurantManagementSystem
```

Замените `<repository-url>` на URL своего GitHub-репозитория.

### 2. Запуск PostgreSQL

Если конфигурация Docker Compose находится в корне проекта, выполните:

```bash
docker compose up -d
```

Проверьте состояние контейнеров:

```bash
docker compose ps
```

### 3. Запуск приложения

Через Maven Wrapper на Windows:

```bash
mvnw.cmd spring-boot:run
```

На Linux или macOS:

```bash
./mvnw spring-boot:run
```

Если Maven Wrapper отсутствует, можно запустить приложение через установленный Maven:

```bash
mvn spring-boot:run
```

Параметры подключения к PostgreSQL должны быть настроены в `application.properties` или `application.yml`.

## REST API

Базовый адрес локального приложения:

```text
http://localhost:8080
```

Основные группы эндпоинтов:

| Метод | Эндпоинт | Описание |
|---|---|---|
| GET | `/user` | Получить список пользователей |
| GET | `/user/{id}` | Получить пользователя по ID |
| POST | `/user` | Создать пользователя |
| PUT | `/user/{id}` | Обновить пользователя |
| DELETE | `/user/{id}` | Удалить пользователя |
| GET | `/categories` | Получить список категорий |
| POST | `/categories` | Создать категорию |
| PUT | `/categories/{id}` | Обновить категорию |
| DELETE | `/categories/{id}` | Удалить категорию |
| GET | `/menu-items` | Получить список блюд |
| POST | `/menu-items` | Создать блюдо |
| PUT | `/menu-items/{id}` | Обновить блюдо |
| DELETE | `/menu-items/{id}` | Удалить блюдо |
| GET | `/orders` | Получить список заказов |
| POST | `/orders` | Создать заказ |
| PUT | `/orders/{id}` | Обновить заказ |
| DELETE | `/orders/{id}` | Удалить заказ |
| GET | `/order-items` | Получить список позиций |
| POST | `/order-items` | Добавить позицию в заказ |
| PUT | `/order-items/{id}` | Обновить позицию |
| DELETE | `/order-items/{id}` | Удалить позицию |

> Список отражает предполагаемые маршруты текущей реализации. Перед публикацией сверьте его с фактическими контроллерами проекта.

## Примеры запросов

### Создание категории

`POST /categories`

```json
{
  "name": "Кофе"
}
```

### Создание блюда

`POST /menu-items`

```json
{
  "name": "Капучино",
  "description": "Эспрессо с молоком и молочной пеной",
  "price": 260.00,
  "category": {
    "id": 1
  }
}
```

### Создание заказа

`POST /orders`

```json
{
  "user": {
    "id": 1
  }
}
```

### Добавление позиции в заказ

`POST /order-items`

```json
{
  "quantity": 2,
  "price": 260.00,
  "order": {
    "id": 1
  },
  "menuItem": {
    "id": 1
  }
}
```

Примеры предполагают, что связанные записи уже существуют в базе данных.

## Тестирование API

Для ручного тестирования запросов можно использовать [Postman](https://www.postman.com/).

Рекомендуемый порядок:
1. Создать пользователя.
2. Создать категорию меню.
3. Добавить блюдо в категорию.
4. Создать заказ.
5. Добавить одну или несколько позиций в заказ.
6. Изменить статус заказа.
7. Проверить получение, обновление и удаление записей.

## Планы развития

- Создание заказа сразу со всеми позициями в одном запросе.
- Автоматический расчёт итоговой стоимости заказа.
- Получение цены блюда на сервере, а не из запроса клиента.
- Хеширование паролей и реализация безопасной авторизации.
- Разграничение доступа по ролям.
- Обработка ошибок и единый формат ответов API.
- Автоматические тесты.
- Документация API с использованием OpenAPI / Swagger.
